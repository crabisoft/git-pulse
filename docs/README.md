# Documentation

Three collections, and the difference between them is who is asking.

| | |
|---|---|
| [**`user/`**](user/) | **How to read it.** The user guide: what each page answers, what the figures on it mean, which setting moves them. For whoever reads the dashboard rather than runs it |
| [**`technical/`**](technical/) | **How it works.** One subject per file — what is stored, what is recomputed, what each module owns, and why each behaviour is the way it is |
| [**`runbooks/`**](runbooks/) | **What to do about it.** Backups, upgrades, the master key, a collection that has stopped, a budget that is spent |
| `images/` | The screenshots the README shows. Generated by `npm run screenshots -w @repo/front`, never cropped by hand |

The first is the odd one out: reStructuredText rather than Markdown, because
Read the Docs publishes it one build per version and a file in a repository only
ever shows the tip of a branch. Reading it here works; reading the version you
run is what it is for — [how that is wired](technical/user-guide.md).

## Where to start

**Evaluating it.** The [README](../README.md) has the screenshots and a
two-command start. [The demo dataset](technical/demo.md) fills an install with a
fictional organization, so there is something to click through before any
credential exists.

**Operating it.** [Running it](technical/operations.md) covers the stacks, the
published images, the background jobs and the migrations. Then read
[backup and restore](runbooks/backup-and-restore.md) before you need it — an
install is two volumes, and one of them is not the database.

**Changing it.** [`CONTRIBUTING.md`](../CONTRIBUTING.md) for setup and what a
change is expected to carry, then
[Collection and metrics](technical/collection-and-metrics.md) before touching
anything that stores or computes a number. That one document explains what is
written to the database and what is recalculated on every request, and getting
the distinction wrong is the easiest way to publish a wrong figure.

**Reporting a security flaw.** [`SECURITY.md`](../SECURITY.md) — not an issue.

## A note on how these are written

They state the reasoning, not only the behaviour: why a value and its chart can
disagree, why the archive is the one table that is never swept, why the reserve
gives up a lead-time segment rather than a repository. That is deliberate. The
behaviour can be read from the code; the reason it was chosen cannot, and it is
what a reader needs before changing it.

Some of these documents were written in French first and translated. If a
sentence reads oddly, it probably is odd — an issue or a pull request on it is
as welcome as one on the code.
